# MoviePilot 课程人工整理

这是一个轻量的 MoviePilot 操作插件。它只负责识别、候选选择和人工确认，不再维护第二套目录、搬运、刮削或通知配置。

## 普通使用流程

1. 打开插件，默认进入“安全预览与人工确认”。
2. 查看识别来源（TMDB、豆瓣、DeepSeek 或本地）。
3. 需要时点击“按名称搜索 TMDB”，从候选中选择作品，无需手填 TMDB ID。
4. 修改建议名称、选择目标媒体库，点击“确认整理”。
5. MoviePilot 原生整理链完成命名、搬运、历史记录、后续事件和按系统规则启用的刮削。
6. 成功后该条从待处理列表消失；失败时原条目和人工决定保留。

“跳过”和“关联 TMDB”只保存决定，不移动文件。确认只处理当前一条，不触发全量整理。
手动选择 TMDB 候选后，建议名称立即使用该候选显示的 TMDB 标题和年份；只有用户随后手动编辑时才覆盖这个名称。

## 目录在哪里配置

统一在 MoviePilot：

**设置 → 存储 & 目录**

至少准备三条明确规则：

| 用途 | 媒体类型 | 来源示例 | 目标示例 |
|---|---|---|---|
| 电影 | 电影 | `/media/incoming` | `/media/movies` |
| 电视剧 | 电视剧 | `/media/incoming` | `/media/tv` |
| 儿童课程 | 电视剧 | `/media/incoming` | `/media/courses` |

儿童课程规则的目录别名（名称）应明确包含“儿童”“少儿”“幼儿”或“课程”，让插件可以无歧义地识别；插件不会根据目标路径中的 `courses` 等片段猜测媒体库类型。搬运方式、智能重命名、刮削、通知、覆盖策略和媒体库子目录也全部在这三条 MoviePilot 规则中设置。

插件只读取这些规则，不会自动创建、修改或覆盖 MoviePilot 系统配置。规则缺失、同类规则重复、来源不一致或不是本地存储时会停止当前确认并提示修正。

人工复核期间，不要让同一来源目录同时被 MoviePilot 自动监控整理，否则文件可能在确认前被原生监控任务处理。操作台会检测并提示仍启用监控的匹配规则。

## 插件自身设置

普通用户不需要配置目录、扫描周期、Preview/Apply、启用开关或“运行一次”。插件设置只保留高级识别偏好：

- 识别来源顺序；
- 自动采用阈值与领先幅度；
- 是否追加 TMDB ID；
- 是否启用 MoviePilot 当前 AI 提供商辅助复核；
- 一次性清空识别缓存。

AI 复核复用 MoviePilot 的全局 AI 配置，不单独保存 DeepSeek Key。

## 安全边界

- 人工复核 API 仅允许启用中的超级管理员访问。
- 原始目录、预览版本和目录树指纹必须与确认时完全一致。
- 没有可靠 TMDB/豆瓣媒体 ID 时，确认前会要求先按名称搜索并关联。
- 人工最终名称只在当前确认目录和当前整理线程中覆盖 MoviePilot 重命名上下文，不影响其他整理任务。
- 只有 MoviePilot 原生整理成功后才消费人工决定并标记完成。
- 文件已移动但复核记录保存失败时返回部分失败并阻止重复确认。
- 旧版目录和调度字段只用于升级兼容，不再出现在普通配置界面，也不是新流程的配置来源。
